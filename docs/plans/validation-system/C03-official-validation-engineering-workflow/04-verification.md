# Phase C03.4: Verify The Validation-Engineering Workflow

## Status

`Provisional`. Execution depends on implemented C01, its focused B03 bootstrap

## Contract Scenarios

Version fixtures must cover:

- setup from explicit workspace evidence and human domain input;
- immutable Domain and Sensorium artifacts with exact config relationships;
- pass, fail, blocked, skipped, timeout, interrupted, invalid, and internal
  validation outcomes where applicable;
- immutable Incident and Drift artifacts with exact parent/report references;
- all three continuation modes at both eligible edges;
- fresh-context resumption from exact artifact paths and digests;
- missing, stale, mismatched, ambiguous, oversized, or hostile evidence;
- partial remediation authority and narrow proof before a final gate;
- policy changes that invalidate cached decisions without rewriting evidence;
- missing resources that stop without implicit Manager or network activity.

## CLI Suite Binding

The verification matrix must also prove that:

- direct and launcher-routed Validator, Manager, and Tool calls used by the
  workflow reach the same sibling executables and produce equivalent semantic
  results;
- every process records the exact B04 suite version, selected component
  identity, resolved executable path, coherence result, and available
  distribution provenance required by C01;
- a missing, substituted, or version-incompatible sibling stops before node
  execution, continuation, validation, mutation, or artifact persistence;
- no workflow resource assigns capability or authority to the launcher itself.

## Genericity Proof

Run the same application contracts against an external fixture workflow with
non-numeric nodes, branching and joining edges, different profiles, different
artifact declarations, and a compatible alternative operational skill. Source
assertions reject official IDs in CLI control flow.

## Evaluation Handoff

C03 owns deterministic workflow fixtures and observable assertions. D01 owns
cross-model runs, comparative scoring, integrated isolation, and system-level
readiness evidence.

## Exit Criterion

The official workflow is resumable, policy-governed, evidence-bound, and
replaceable, with no dependence on a particular chat layout or model provider.
