# WCAG 2.2

## Scope And Version

W3C Web Content Accessibility Guidelines (WCAG) 2.2 is a W3C Recommendation
dated 5 October 2023. It defines testable success criteria for Web content under
principles of perceivable, operable, understandable, and robust.
[Source: w3c.wcag-2.2#status-and-scope](https://www.w3.org/TR/WCAG22/#abstract)

## Native Conformance Model

WCAG retains Levels A, AA, and AAA. Conformance at a level requires satisfying
all criteria at that level and lower levels, plus the conformance requirements.
AAA is not recommended as a general policy for entire sites because some
content cannot satisfy all AAA criteria.
[Source: w3c.wcag-2.2#conformance-levels](https://www.w3.org/TR/WCAG22/#levels-of-conformance)

These levels apply only within WCAG 2.2's scope. Do not translate them into a
universal product assurance, security, maturity, or risk score.

## Evidence And Limitations

Automated checks can detect selected machine-observable failures. Manual and
assistive-technology evaluation is needed where a success criterion depends on
meaning, interaction, or user experience. Passing a tool is not a conformance
claim; any claim must identify scope, version, level, pages/processes, and relied
upon technologies.

## Selection And Next Step

Identify affected Web content and users, select exact success criteria and
conformance scope, then combine automated, code-review, keyboard, visual, and
assistive-technology evidence as applicable. If the product is terminal or
native UI rather than Web content, use WCAG only as a clearly labeled source of
relevant principles and do not claim WCAG conformance without an applicable
scope.
