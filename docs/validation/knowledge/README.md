# Shared Validation Knowledge

This is the canonical, audience-neutral knowledge base for choosing and
interpreting validation evidence. Start with the compact [catalog](catalog.json)
and load only the documents that match the current question and confirmed
workspace facts.

1. Use [foundations](foundations/README.md) for the reasoning model.
2. Add a reusable [pattern](patterns/README.md) when the evidence design needs
   it.
3. Load an exact language, framework, technology, tool, concern, or standard
   guide only when its applicability is confirmed.
4. Use a [recipe](recipes/README.md) as an example of composition, never as
   mandatory project policy.
5. Follow a registered [source location](SOURCES.md) only when local guidance
   is insufficient and external access is available and authorized.

The catalog's applicability fields are routing hints, not claims about a
workspace. Missing coverage is explicit: inspect authoritative material or
report the gap instead of inventing local guidance. Loading this tree never
selects a product flow, starts a process, executes a command, persists an
artifact, or authorizes network access.

`sources.json` is the canonical source register; `SOURCES.md` is generated.
The copy under the distributed skill is generated byte-for-byte from this tree.

## Repository Maintenance

After editing canonical knowledge or `sources.json`, regenerate the source index
and exact skill projection:

```sh
cargo run --locked --example knowledge_release -- --write
```

Release and CI checks use the non-mutating form:

```sh
cargo run --locked --example knowledge_release -- --check
```

The check validates registries, IDs, vocabularies, relationships, citations,
internal links, indexes, routing/evaluation fixtures, generated bytes, and the
host-independent `sha256-tree-v1` digest.
